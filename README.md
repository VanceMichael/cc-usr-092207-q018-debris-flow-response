# 泥石流搜救态势板

汇总泥石流失联人员、搜索网格、队伍资源和权威通报。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括应急指挥人员、现场搜救队伍、现场签到点、家属联络人员、权威信息发布人员。

资料所依据的领域事实如下（截至九月十九日深夜，五人中两人已被找到，其余三人搜救中）：

- 局部强降雨在石家沟隧道附近引发泥石流险情
- 截至九月十九日深夜，最初五名失联人员中两人已被找到
- 其余三名失联人员的搜救仍在石家沟隧道附近持续
- 再降雨可能触发二次灾害，必须能按气象地质警报立即停工撤离

## 实时态势要素（situation_elements）

以下八类信息汇成实时态势，指挥员打开系统即应看到覆盖情况、未确认人员、资源占用方与下一次通报依据：

1. **灾害边界** —— 实际影响范围（含石家沟隧道口及沟谷），边界变更留痕
2. **气象地质警报** —— 降雨与次生灾害预警等级，驱动停工撤离决策
3. **家属核验** —— 每名失联人员一条权威身份记录，找到与仍失联分别标记确认状态
4. **搜索网格** —— 覆盖状态（未开始 / 进行中 / 已覆盖 / 需重搜），重搜登记原因
5. **队伍能力** —— 各队资质与可执行任务类型（绳索、破拆、犬搜、医疗等）
6. **车辆装备** —— 归属、位置与占用状态，被谁占用可查
7. **进出记录** —— 人员车辆经签到点进入危险区的时间、同行人和方向
8. **人员交接** —— 班次交接时现场实有人员与任务的双签确认

## 只追加事件（event_log_types）

重复报警、坐标修正、再降雨停工、网格重搜和轮班只能追加事件顺序，不得删除或覆盖：

- **重复报警** —— 同一线索重复报入时合并到既有档案并指向原记录
- **坐标修正** —— 对已发布坐标的修正形成新版本，不覆盖旧值
- **再降雨停工** —— 警报触发的停工撤离，记录通知与回执情况
- **网格重搜** —— 已覆盖网格因新线索重搜，只追加原因与批准人
- **轮班** —— 进出与交接双签事件，不改写历史班次记录

## 关键约束

- 名单、搜索区域与对外表述必须**同步更新**，避免队伍携带过期信息进入石家沟隧道附近危险地带
- 弱网现场可**离线领取签名任务**，恢复连接后回传；任务分配与完成以签名为准
- 家属联络岗位**只看必要身份信息**，不暴露搜救部署细节
- 新闻发布**只引用已确认状态**，不发布未经核验的信息

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、态势要素、事件类型和约束。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
